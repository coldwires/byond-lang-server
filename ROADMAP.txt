WHAT WE ARE BUILDING
--------------------------------------------------------------------------------
  Dm.Core     C# library that parses and understands DM. ~85% of the work,
              shared by every shell.
  Dm.Native   NativeAOT wrapper -> dm_core.dll, the C ABI for the Qt IDE and
              anything else with a C FFI.
  Dm.Cli      dmc, the dev driver. Fastest debug loop and the arbiter when an
              IDE reports a bug: if the CLI reproduces it, it is ours.
  Dm.Lsp      LSP server for VS Code / Neovim / everyone else.        [M10]
  Dm.Assets   .dmi icon state reader.                                  [M8]

  WHAT CHANGED AND WHY
    Syntax highlighting was at M9/M10 as a TextMate grammar plus LSP semantic
    tokens. Neither does anything for an FNA/C# window or a Qt IDE. What those
    need is a classify-this-range call returning coloured spans, and that needs
    the LEXER ONLY - so it moved to M2, and first visible payoff moved from M6
    to M2. Document symbols moved to M4 for the same reason: a per-file outline
    needs the AST, not the object tree.


WHY DM IS HARD                        (one line each; the detail is in PLAN.md)
--------------------------------------------------------------------------------
  Dots and slashes         mid-path "." and "/" are the SAME token, "proc" and
                           "verb" are ordinary segments, and a LEADING "." is a
                           search rather than a traversal.            PLAN 4a
  Include order is semantic  overrides resolve by .dme order, so editing a
                           #define invalidates everything downstream. And
                           "var.thing.T" parses differently depending on
                           whether /thing was declared yet - swapping two
                           #include lines flips it.                   PLAN 4a
  Two block syntaxes       braces AND significant indentation, mixed in one
                           file, nesting freely in either order.      PLAN 8
  Builtins are invisible   mob.Move(), .loc, .client appear in no user code and
                           must be scraped from the BYOND reference.  PLAN 6/M5
  Macro-heavy reality      without source maps every completion and error lands
                           on the wrong line.                         PLAN 6/M3
  Error recovery           editor buffers are broken on every keystroke.
  ":" is not unchecked     it WIDENS the check to subtypes. filtering it to
                           nothing, or to everything, are both wrong.  PLAN 4a
  Nesting block comments   DM nests /* */, unlike C.                   PLAN 8
  Odd but legal forms      comma var lists, ";" separators, single-line proc
                           bodies, default params, bare inherited-var
                           assignment, operator overloads incl. operator:=
                           (which contains a colon).                   PLAN 4c
  Position encoding        LSP wants UTF-16, the C ABI wants UTF-8 bytes.
                           Support both or retrofit every signature.   PLAN 4
  NativeAOT constraints    no reflection or dynamic in Dm.Core, no exception
                           may cross the boundary, per-platform binaries.
                           PLAN 7
  We become the platform   two IDEs depend on our ABI. Breaking changes cost
                           other people real work.

--------------------------------------------------------------------------------
  src\_constants.dm is included TWICE (spies.dme lines 7 and 9). Harmless, the
  compiler ignores the repeat. Line 9 is inside DreamMaker's auto-generated
  block, so line 7 is the redundant one.

  8 .dm files on disk are NOT reached by spies.dme, so they are dead unless
  something else pulls them in:

      src\lighting\daynight.dm        src\lighting\sun.dm

CONVENTIONS
--------------------------------------------------------------------------------
  - PLAN.md, ROADMAP.txt, INTEGRATION.txt and docs/dm-language-notes.md are all
    LIVE docs: they describe now, at every commit.
  - docs/internal/ is Claude's working notes. Gitignored. Not team-facing.
  - EVERY NEW FINDING GETS A FIXTURE CASE, in the same change. tests/fixtures
    is the regression net; anything left out of it gets re-learned. A corpus of
    correct code cannot tell us what we wrongly ACCEPT - dm.exe reports zero
    diagnostics on tgstation's 1.5M lines - so the must-fail and must-mean-this
    cases only exist if someone writes them.
  - Commits: concise and factual. Group related changes; don't split per line,
    don't lump unrelated work together. No AI attribution lines.
  - Prose: no hype, no "it's not X, it's Y", fact-driven.
